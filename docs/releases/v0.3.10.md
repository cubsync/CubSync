<summary><h3>中文说明</h3></summary>

这一版把**对比档、卡片/缩略档、栏头手势、传送条**做成原型里的样子，并把几个一直在界面上承诺、
实际没做到的控件补成真的。

#### 界面对齐

**对比档。** 以前是一张表：左边名称、右边名称、一列「差异」。现在两端都回到原型的样子——仍然是两栏，
按名称逐行对齐，差异用左侧色条标记，另一侧没有的文件在这里是灰行，写「对侧缺失 · 将创建」。
只有一栏切成对比时两栏都会显示，因为一栏没法跟自己对。

**手机卡片 / 缩略档。** 以前每个格子占满一行，设「列数」等于没设。现在是真的网格，列数就是设置里那个数。

**手机副行最右边的 ⋮。** 改成原型的「更多」：新建文件夹 / 多选 / 收藏当前目录 / 收藏列表 / 放大条目 /
缩小条目。排序与作用范围还在每一栏自己的 ⋮ 里，两处不再混用。

**多选。** 打开后单击行是勾选，目录也不再进入——以前没有这个模式。

**手机栏头。** 长按空白复制地址，长按 ← 回本栏根目录，横滑不会误当成点击；双栏窄屏按设置的行数显示，
上面几行是父路径、最后一行是当前目录名。

**桌面行尾的 ⋮ 去掉了。** 改成右键出动作面板——界面一直写着「右键理管」，此前并没有实现。

#### 说到的都做到了

**传送条**有了进度条、百分比、暂停/继续、取消。暂停真的停在块与块之间，继续从同一块往下走；取消会中止
写到一半的文件，不会留下一个正式名字的残文件。

**同步作业也能暂停/继续**（以前只有取消）。

**「断点续传」开关**现在真的传给引擎：关掉之后中断的文件下次整份重传。

**「默认接收目录」**现在真的生效：对面那栏还没打开目录时，传送落到这里。

**「缓冲块数」**写明现状：值会记住，读写目前仍按 1MB 块顺序进行，并行块队列还没接上。

#### 修掉的

- 对比档里另一栏是空的时候，显示「这个文件夹是空的」，看不到「将创建」的行。
- 手机「传送 ▸ 远端」在选中远端文件时方向写错，应该写「传送 ▸ 本机」。
- 设置页「默认接收目录」的副标题写死了路径，「默认显示方式」写死了行高。
- 桌面详情卡上的「在新窗口打开所在目录」按了没反应；现在真的打开，且只对本机那一栏出现。

#### 你这一版要验的

1. 两端切到对比档，缺项是不是灰行、差异色条对不对；
2. 手机卡片/缩略档改列数，格子真的跟着变；
3. 两端传一个文件夹，暂停再继续，进度是不是接着走；
4. 桌面右键一行，动作面板出不出来。

<summary><h3>English</h3></summary>

This release makes 对比 (compare), 卡片/缩略 (card / thumbnail), the pane-header gestures
and the transfer strip look like the prototype, and turns several controls that the
interface had been promising into ones that do something.

#### Aligned with the design

**Compare.** It used to be one table: a name, another name, and a 差异 column. Both ends
now do what the prototype does — still two panes, rows aligned by name, the difference
marked as a coloured edge, and a dimmed row saying 对侧缺失 · 将创建 where the other side
has something this one does not. Selecting compare in either pane shows both, because one
listing cannot compare with itself.

**Card and thumbnail on the phone.** Every tile used to take a whole row, so the column
count did nothing. It is a real grid now, and the count is the one in the settings.

**The ⋮ at the end of the phone's sub-row** is the prototype's 更多 panel: new folder,
multi-select, favourite this folder, the favourite list, zoom in, zoom out. Sorting and
scope stay in each pane's own ⋮; the two no longer open the same list.

**Multi-select.** While it is on, a tap ticks a row — folders included — instead of
entering them.

**The phone's pane header.** Long-press the blank part to copy the address, long-press ←
to go back to this pane's root, and a sideways drag no longer counts as a tap. In a
two-pane portrait layout the header uses the line count from the settings: ancestors
above, the current folder last.

**The desktop's per-row ⋮ is gone.** Right-clicking a row opens the action panel — the
screen has said 右键理管 all along, and nothing was listening.

#### Promises kept

**The transfer strip** has a progress bar, a percentage, pause/resume and cancel. Pausing
stops between blocks and resuming continues from the same block; cancelling aborts the
half-written file rather than leaving a fragment under its real name.

**A sync run can be paused** now, not only cancelled.

**The 断点续传 switch** is passed to the engine: with it off, an interrupted file is
copied again from the start.

**默认接收目录** is honoured: when the far pane has not been pointed anywhere, a transfer
lands there.

**缓冲块数** now says what it is: the value is remembered, but reads and writes still go
one 1MB block at a time until the parallel block queue is wired.

#### Fixed

- Compare showed 这个文件夹是空的 in the pane that had nothing, hiding the rows that were
  about to be created.
- The phone's transfer button said 传送 ▸ 远端 even when the selection was on the remote
  side.
- The settings screen hard-coded a path under 默认接收目录 and a row height under
  默认显示方式.
- 在新窗口打开所在目录 on the desktop's detail card did nothing; it opens the folder now,
  and only for the local pane.

#### Worth checking in this build

1. Compare on both ends: are the missing rows dimmed and the difference edges right?
2. Change the column count in card/thumbnail on the phone: do the tiles follow?
3. Transfer a folder and pause it: does resuming continue where it stopped?
4. Right-click a desktop row: does the action panel appear?
