<summary><h3>中文说明</h3></summary>

这一版把界面上两句**做不到的话**补成了真的。

#### 修好了

**条目缩放的两个手势现在真的存在。** 规格写着「双击列表＝缩放复位 100%」「Ctrl+滚轮＝连续缩放 0.7×–2.0×」，手机端写着「双指缩放 0.7×–2.0× · 双击复位」——而这三句话之前只是字：全仓没有任何手势处理器在听。界面在承诺它做不到的事。

现在：

- **桌面**：按住 Ctrl 滚滚轮连续缩放；在列表空白处双击回到 100%。
- **手机**：双指捏合连续缩放；双击回到 100%。
- 缩放只在**两指**时接管事件（手机），所以单指拖动照旧滚列表、单击照旧进目录——一个无条件的变换检测器会把这两件事一起吃掉，那比缺少手势更糟。

**为什么这算 BUG 而不是新功能**：它不是新增能力，是让界面停止说谎。数值本身（70%–200%、步进、出厂 100%）早就写在规格里，只有"怎么改它"没接上。

#### 顺带

- `ItemScale.zoomBy()` 抽成纯函数并加了五个单测（缩放是乘法的、十次 1% 要能累加、两端夹紧、以及 NaN/0/负数这类手势库会递过来的垃圾值不改变任何东西）。手势的**接线**无法自动化验证——那部分只能实机走查。
- 行高仍然由同一个数值驱动，两端一致。

<summary><h3>English</h3></summary>

This release turns two sentences the interface could not keep into ones it can.

#### Fixed

**The two item-scale gestures now exist.** The specification says 双击列表＝缩放复位 100%
and Ctrl+滚轮＝连续缩放 0.7×–2.0×, and the phone's settings say 双指缩放 0.7×–2.0× · 双击复位.
Until now those were only words: nothing in either end was listening. The interface was
promising something it could not do.

- **Desktop**: hold Ctrl and turn the wheel to scale continuously; double-click the blank
  part of a listing to return to 100%.
- **Phone**: pinch to scale continuously; double-tap to return to 100%.
- Scaling takes over the event only when there are **two** fingers, so a one-finger drag
  still scrolls the list and a tap still opens a folder. An unconditional transform
  detector would swallow both, which is worse than a missing gesture.

**Why this is a bug and not a feature**: it adds no capability, it stops the interface from
lying. The numbers themselves — 70% to 200%, the step, the factory 100% — were already in
the specification; only the gesture that changes them was missing.

#### Also

- `ItemScale.zoomBy()` is a pure function with five unit tests (a pinch is multiplicative,
  ten one-per-cent pinches add up, both ends hold, and the NaN, zero and negative values a
  gesture library can hand over change nothing). The **wiring** cannot be tested here; it
  needs a real device.
- Row height is still driven by that one number, the same on both ends.

</details>
