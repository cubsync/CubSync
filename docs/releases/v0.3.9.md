<summary><h3>中文说明</h3></summary>

这一版把界面上**数值与用词**按原型和规格对齐，并修掉一个一直在红的测试。

#### 改好了

**图标的点击区域。** 规格 §5 要求图标按钮 26–34px，原型里 `.iconbtn` 是 28px。桌面有四处在 22–24px——**比下限还小**，鼠标要瞄。现在统一 28px（六处）。

**禁用词。** 规格 §2 有一张定名表，两端必须逐字一致。清掉的：`对端→远端`、`本地版本→本机版本`、`垃圾箱→回收站`、`对比视图→对比档`、`是全局的→两栏都生效`。

手机顶栏那几个 38px 的按钮**没有动**——原型里就是 38px，改小反而偏离。

#### 修了一个测试，也承认一次没修对

`AppStateTest` 里「进子目录再返回」那条测试反复红。我上一版（0.3.6 那次提交）以为修好了，**其实没有**：它当时只是碰巧在 CI 上绿。

这次用临时探针打出了实际值：`up()` 是**同步生效**的，栏位一步从 `…/holiday` 回到父目录——导航本身没问题。红的是测试里那条**额外条件**（还要求列表里出现 `holiday` 且不在 loading），它把「导航对不对」和「列表什么时候回来」混在一件事里测。条件已收敛到它真正要测的东西。

#### 你这一版要验的

1. 桌面图标按钮是不是好点了（尤其每栏右上那颗 `⋮`）；
2. 连接页/设置页的措辞有没有变顺；
3. 上一版的安卓权限那三件（若你还没验）。

<summary><h3>English</h3></summary>

This release aligns the interface's numbers and words with the prototype and the
specification, and fixes a test that had been red for a while.

#### Fixed

**Icon hit areas.** §5 of the specification asks for 26–34px; the prototype's
`.iconbtn` is 28px. Four desktop buttons were 22–24px, below the floor, so a mouse
had to aim. All six are 28px now.

**Forbidden words.** §2 is a fixed vocabulary that both ends must match word for
word. Gone: 对端, 本地版本, 垃圾箱, 对比视图, 是全局的.

The phone's 38px top-bar buttons are untouched — the prototype's are 38px too.

#### A test I had already claimed to fix

`AppStateTest`'s "enter a subfolder, come back" test kept failing. A previous
release claimed to fix it; it had not — it merely happened to be green on CI. A
temporary probe printed the actual values: `up()` takes effect synchronously and
the pane goes from `…/holiday` straight to its parent, so navigation was never
broken. What was broken was an extra condition in the test — it also demanded the
listing arrive, mixing "did navigation happen" with "when did the listing come
back" in one assertion. It now asserts the first.
