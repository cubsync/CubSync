<summary><h3>中文说明</h3></summary>

这一版修的是**真机上才会出现**的两个问题，以及一件让它们迟到的流程错误。

#### 修好了

**安卓上打开文件夹只能看到文件夹，看不到任何文件。** 原因是 Manifest 里**只有三个网络权限，没有任何存储权限**，代码里**也没有一处运行时申请**。而 manifest 的注释把理由写得很确定：「它不是媒体浏览器，读的是给它的路径，而现代安卓上那些路径本来就是它能打开的共享存储」。

**那句话是错的。** targetSdk 33 起，没有 `READ_MEDIA_*` 的应用**看得见目录树、看不见里面的文件**——不报错、不弹窗、界面正常，只是东西少了。这一类错误只有真机能发现，所以它活了这么久。

现在补上 `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` / `READ_MEDIA_AUDIO`（API 33+）与 `READ_EXTERNAL_STORAGE`（API 32 及以下），并在进入界面时申请一次，已授过的不重复问。那段把 bug 写进理由的注释，改成了记录这个 bug 本身。

**电脑端长按一行没有反应。** 规格写的是「单击＝进目录/勾选，**长按＝动作面板**」——手机端照此办理，桌面端却只有行尾那颗 `⋮`，**规格指定的入口（那一行本身）按了没反应**。现在两者都有。

#### 为什么上一版没修好

修好了，但**没进到给你的那个包里**：权限修复是在 `v0.3.6` 打标签**之后**才合进主线的，而你装的 APK 是从那个标签构建的。这是我的流程错误——**修完之后应该出新版本号，而不是让你去装一个不含修复的旧包**。

#### 顺带

- 安卓包现在**是 release 签名的**（同一把密钥）。此前每次发的都是 debug 包，因为 CI 里四个签名 secrets 一个都没设，工作流按设计回退成了 debug。**debug 签名的包无法覆盖安装 release 包**，所以这一版可能要先卸载旧版。
- 删掉电脑端 104 行自 0.3.4 起就不可达的代码，它里面还留着上一版才实现的那句手势承诺。

#### 你这一版要验的

1. 打开一个文件夹，**能不能看到文件**（不只是文件夹）；
2. 首次进入**弹不弹**存储权限请求；
3. 电脑端**长按一行**能不能出动作面板。

第 3 条我在本机能验；前两条只有真机能验——**安卓这边我没有设备，这是我的盲区，只能靠你。**

<summary><h3>English</h3></summary>

This release fixes two problems that only appear on a real device, and one process
mistake that made them late.

#### Fixed

**On Android, opening a folder showed the folders and none of the files.** The manifest
declared three network permissions and no storage permission at all, and no code anywhere
asked for one. The comment above those permissions was confident about why: "the app is
not a media browser: it reads the paths it is given, and on a modern Android those paths
are the shared storage it can already open."

**That sentence is wrong.** From targetSdk 33 an application without `READ_MEDIA_*` can see
a directory tree and not the files inside it — nothing throws, nothing is logged, the screen
looks fine and is missing things. Only a real device shows a failure like that, which is
how it survived this long.

`READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO` and `READ_MEDIA_AUDIO` for API 33 and up,
`READ_EXTERNAL_STORAGE` for API 32 and below, and a request on the way into the interface
that asks only for what has not been granted. The comment is now a record of this bug
rather than of the reasoning that caused it.

**Long-pressing a row on the desktop did nothing.** The specification says a tap enters or
ticks and a **long press opens the action panel**; the phone does that, and the desktop had
only a `⋮` at the end of each row, so the entry the specification names did nothing. Both
work now.

#### Why the previous release did not fix this

It did fix it, and the fix was not in the build you installed: the permission change was
merged after `v0.3.6` was tagged, and the APK came from that tag. That is a process mistake
— a fix should get its own version rather than be shipped as a build that predates it.

#### Also

- The Android build is now **release-signed**, with the same key as every future one. Every
  earlier release shipped a debug APK, because none of the four signing secrets existed in
  CI and the workflow falls back by design. A debug-signed build cannot replace a
  release-signed one, so this version may need the old one uninstalled first.
- 104 lines of unreachable desktop code are gone; they still described a gesture that only
  arrived in the previous release.
